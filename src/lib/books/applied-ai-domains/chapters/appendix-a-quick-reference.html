PID Controller

output(t) = kp * e(t) + ki * ∫e(t)dt + kd * de(t)/dt

where:
  e(t) = target - measured (the error at time t)
  kp   = proportional gain
  ki   = integral gain
  kd   = derivative gain
Term Responds to Effect of increasing it Failure mode if too high
P (proportional) Current error Faster response Oscillation / instability
I (integral) Accumulated past error Eliminates steady-state error Slow oscillation (“integral windup”)
D (derivative) Rate of change of error Damps oscillation, reduces overshoot Amplifies sensor noise

PID Tuning Sequence

  1. Set ki=0, kd=0. Increase kp until the system responds quickly but starts to oscillate. Back off to ~50-70% of that value.
  2. Add kd gradually. It damps oscillation and reduces overshoot, but too much amplifies sensor noise.
  3. Add ki only if there’s a persistent steady-state error. Increase it slowly: too much causes slow oscillation (“integral windup”).
Symptom Fix
Slow to reach target Increase kp
Overshoots then oscillates, doesn’t settle Increase kd, or reduce kp
Settles near but not at target Increase ki (P-only steady-state offset)
Oscillates slowly with growing amplitude ki too high: reduce it, or add an integral windup clamp
Twitchy / noisy output kd too high, or measurement is noisy: filter it first

Forward Kinematics: 2-Link Planar Arm

Given joint angles theta1, theta2 and link lengths l1, l2:

x1 = l1 * cos(theta1)
y1 = l1 * sin(theta1)
x2 = x1 + l2 * cos(theta1 + theta2)   # end-effector x
y2 = y1 + l2 * sin(theta1 + theta2)   # end-effector y

For an N-link planar arm, each link’s angle is added to the cumulative angle of all links before it, then the link’s length is projected onto x/y and added to the running position (Listing 58.4).

Stereo Depth Formula

depth = (baseline * focal_length) / disparity

baseline:      distance between the two camera centres
               (metres)
focal_length:  the CALIBRATED pixel focal length
               (not the mm spec-sheet value)
disparity:     pixel shift of the same point between
               left/right views

Kalman Filter: 1D Update Equations

Predict:  x_pred = x + v*dt         P_pred = P + Q
Update:   K = P_pred / (P_pred + R)
          x = x_pred + K*(z - x_pred)
          P = (1 - K) * P_pred
Term Meaning
x Current best estimate
P Variance of the current estimate
Q Process noise: uncertainty added per predict step
R Observation noise: how noisy the sensor reading is
K Kalman gain: weighting on the new observation, in [0, 1]
z The raw observation being fused in

Static two-sensor fusion (no motion model: the form used in this chapter’s worked example):

K_camera = var_imu / (var_camera + var_imu)
K_imu    = var_camera / (var_camera + var_imu)
fused    = K_camera * camera_obs + K_imu * imu_obs

ICP Algorithm (Simplified)

Repeat until convergence:
1. For each source point, find its nearest neighbour in the target
2. Solve for the rigid transform (R, t) best mapping
   matched source points onto their matched target
   points (Kabsch algorithm via SVD)
3. Apply (R, t) to all of source
4. Stop when the mean point-to-point error stops improving

def mask_indices(n_patches, mask_ratio=0.5, min_context=1):
    idx = np.random.permutation(n_patches)
    n_mask = min(
        int(n_patches * mask_ratio),
        n_patches - min_context,
    )
    return idx[n_mask:], idx[:n_mask]

@torch.no_grad()
def ema_update(target_model, online_model, momentum=0.996):
    for pt, po in zip(
        target_model.parameters(),
        online_model.parameters(),
    ):
        pt.mul_(momentum).add_(po, alpha=1 - momentum)

Discretisation Snippet

def discretize_action(
    continuous_action,
    n_bins=256,
    action_range=(-1.0, 1.0),
):
    lo, hi = action_range
    clipped = np.clip(continuous_action, lo, hi)
    return int((clipped - lo) / (hi - lo) * (n_bins - 1))

def undiscretize_action(
    bin_idx,
    n_bins=256,
    action_range=(-1.0, 1.0),
):
    lo, hi = action_range
    return lo + (bin_idx + 0.5) / n_bins * (hi - lo)

Chapter 63 — Learning Robot Policies

Key Terms

Term Definition
Policy A function from observation to action: the object being trained by all three approaches in this chapter
Behaviour cloning Supervised learning of a policy directly from (observation, expert-action) pairs
Distribution shift The failure mode where a policy trained on one distribution of states performs poorly on states outside it
DAgger (Dataset Aggregation) The standard fix for distribution shift: iteratively query the expert at states the trained policy actually visits, and retrain on the aggregated data
Reward shaping Designing a reward function that provides useful learning signal, typically by adding dense intermediate rewards alongside a sparse task-completion reward
Reward hacking A policy exploiting an unintended loophole in a reward function to score well without doing the intended task

Policy-Learning Approach Comparison

Approach Needs a reward function? Needs demonstrations? Sample efficiency Generalisation Typical failure mode
RL Yes No Low (many episodes needed) Good across the trained distribution (incl. domain randomization) Reward hacking; slow convergence
Imitation learning / behaviour cloning No Yes High (if demonstrations available) Only as good as demonstration coverage Distribution shift
VLA fine-tuning Optional (can combine with RL or imitation) Small amount High (leverages pretraining) Broad, from pretrained visual/language priors Inherits pretrained model’s biases/latency cost

DAgger Algorithm Sketch

dataset ← initial expert demonstrations
policy ← train_behaviour_cloning(dataset)

repeat for N iterations:
    # NOT expert rollouts
    visited_states ← rollout(policy, various starts)
    corrections ← [
        (s, expert_action(s)) for s in visited_states
    ]
    dataset ← dataset ∪ corrections
    # retrain on aggregated set
    policy ← train_behaviour_cloning(dataset)

Requires an expert that can be queried at arbitrary states (a scripted controller, a human in the loop, or an optimal planner), not just a fixed set of pre-recorded trajectories.

Reward Shaping Pitfalls

Pitfall Symptom Fix
Too sparse No learning progress; reward almost never nonzero early in training Add dense shaping term (e.g. negative distance-to-goal) alongside sparse completion bonus
Reward hacking High reward, visibly wrong/degenerate behaviour Inspect behaviour directly, not just the reward curve; close the loophole
Conflicting terms Policy satisfies no single objective well Start with 1-2 terms, add incrementally
Scale mismatch One term dominates learning regardless of intended weighting Normalise term scales before summing

def staged_rollout(
    update,
    fleet,
    canary_fraction=0.05,
    threshold=0.85,
):
    canary = sample(fleet, canary_fraction)
    canary.apply(update)
    baseline_perf = measure_performance(fleet - canary)
    if measure_performance(canary) >= threshold * baseline_perf:
        (fleet - canary).apply(update)
        return "proceed"
    canary.rollback()
    return "halted"

   66.1): don't assume documented specs match actual

Residual Block Skeleton

class ResBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        self.conv1 = nn.Conv2d(channels, channels, 3, padding=1)
        self.bn1 = nn.BatchNorm2d(channels)
        self.conv2 = nn.Conv2d(channels, channels, 3, padding=1)
        self.bn2 = nn.BatchNorm2d(channels)
        self.relu = nn.ReLU()
    def forward(self, x):
        identity = x
        out = self.relu(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        return self.relu(out + identity)

def compute_iou(box1, box2):
    x1, y1 = max(box1[0], box2[0]), max(box1[1], box2[1])
    x2, y2 = min(box1[2], box2[2]), min(box1[3], box2[3])
    inter = max(0, x2 - x1) * max(0, y2 - y1)
    area1 = (box1[2] - box1[0]) * (box1[3] - box1[1])
    area2 = (box2[2] - box2[0]) * (box2[3] - box2[1])
    union = area1 + area2 - inter
    return inter / union if union > 0 else 0.0

def nms(boxes, scores, iou_threshold=0.5):
    order = sorted(
        range(len(scores)),
        key=lambda i: scores[i],
        reverse=True,
    )
    keep = []
    while order:
        i = order.pop(0)
        keep.append(i)
        order = [
            j for j in order
            if compute_iou(boxes[i], boxes[j]) < iou_threshold
        ]
    return keep

ViT Architecture Steps

1. Slice image into fixed-size patches (e.g. 16x16)
2. Flatten + linearly project each patch -> embedding
3. Prepend a learnable [CLS] token
4. Add positional embeddings
5. Feed through a standard transformer encoder (unmodified)
6. [CLS] token's output -> classification head

Patch Size Trade-off

Sequence length = (image_size / patch_size) ** 2
Smaller patches -> longer sequence -> quadratically more
  attention compute, finer spatial granularity.
Larger patches -> shorter sequence -> cheaper, coarser granularity.
Common default: 16x16 patches for 224x224 images.

Reparameterisation Trick

def reparameterise(mu, logvar):
    std = torch.exp(0.5 * logvar)
    eps = torch.randn_like(std)
    return mu + eps * std

VAE Loss

Term Formula Role
Reconstruction loss MSE(x_hat, x) Pushes decoder output to match input
KL divergence -0.5 * sum(1 + logvar - mu^2 - exp(logvar)) Pulls encoder distribution toward N(0,1)

Mode Collapse Diagnostic

def diversity_check(generator, latent_dim, n_samples=50):
    z = torch.randn(n_samples, latent_dim)
    with torch.no_grad():
        samples = generator(z).view(n_samples, -1)
    dist = torch.cdist(samples, samples)
    return dist[~torch.eye(n_samples, dtype=bool)].mean().item()

def random_walk(G, start, walk_length):
    walk = [start]
    for _ in range(walk_length - 1):
        neighbors = list(G.neighbors(walk[-1]))
        if not neighbors:
            break
        walk.append(random.choice(neighbors))
    return walk

Multi-Hop Traversal Pseudocode

function multihop_answer(G, condition_fn, buyer):
    # e.g. flagged == True
    candidates = filter(G.nodes, condition_fn)
    buyer_targets = out_neighbors(buyer, relation="PURCHASES_FROM")
    for candidate in candidates:
        for owner in in_neighbors(candidate, relation="OWNS"):
            siblings = out_neighbors(owner, relation="OWNS")
            for sibling in siblings - {candidate}:
                if sibling in buyer_targets:
                    # the full hop chain
                    yield (candidate, owner, sibling)

Adaptive Search Skeleton

def agentic_search(
    start_nodes,
    target_set,
    get_neighbors,
    max_hops=6,
):
    frontier, visited = set(start_nodes), set(start_nodes)
    for hop in range(1, max_hops + 1):
        new_nodes = set()
        for node in frontier:
            new_nodes |= get_neighbors(node) - visited
        if new_nodes & target_set:
            return {
                "found": True,
                "hop": hop,
                "match": new_nodes & target_set,
            }
        visited |= new_nodes
        frontier = new_nodes
        if not frontier:
            break
    return {"found": False}

Hop Budget Trade-off

Setting Risk
Too tight Silent failure: gives up before finding real, further answers
Too loose Slow; risks flooding a downstream prompt with irrelevant context

What Prevents Infinite Loops

Mechanism Role
visited set Ensures correctness: each node explored exactly once
max_hops Safety ceiling on top of that: not what makes the loop correct
