Chapter 59 turns raw sensor data into structured observations. Chapter 60 predicts how those observations will change. Neither one, on its own, tells a robot what to do. Something has to go from “here’s what I see, here’s what I’ve been asked to do” to a motor command. Traditionally that meant hand-engineering a policy for each task, one program for grasping, another for navigation, another for placing an object in a bin, none of which transferred to a new object, a new instruction phrasing, or a new environment. A vision-language-action (VLA) model is the alternative: a single model that takes an image and a natural-language instruction and outputs an action, trained end-to-end on data from many tasks, so the broad visual and linguistic generalisation of an internet-pretrained model transfers to the action-prediction problem too.

61.1 Motivation

The insight that makes VLA models work is simple once Book 2’s transformers and prompt engineering chapters are in hand: a transformer that predicts the next language token and a transformer that predicts the next action token are doing the same computation. If an action can be represented as a token, a discrete symbol from some fixed vocabulary, then “predict what to do next” becomes just another instance of autoregressive next-token prediction, the same mechanism a chatbot uses to predict the next word. This is exactly what RT-2 (Robotics Transformer 2) did: take a vision-language model already pretrained on internet-scale image-text data, discretise the robot’s continuous action space (arm position deltas, gripper state) into bins, represent each bin as an extra token appended to the model’s existing vocabulary, and fine-tune on robot trajectories labelled with these action tokens. The model that used to output “the cat sat on the ” now also outputs ”move the arm ”: same architecture, same training objective, extended vocabulary. Worked Example 61 below trains a minimal VLA and runs a targeted ablation proving it genuinely conditions on both modalities, not just one.

61.2 Exposition

61.2.1 Three Architectural Families

Discrete action tokens (RT-2) bin a continuous action space into a vocabulary, predicted autoregressively like language: reuses the entire LLM training/inference stack unchanged, but discretisation loses precision for fine manipulation. Open-weight VLA backbones (OpenVLA, built on Llama) use the same discrete-token idea on an open LLM backbone: same trade-offs as RT-2, but inspectable and fine-tunable by anyone rather than locked behind an API. Continuous action heads (π0\pi_0π0​-style models) use a small diffusion or flow-matching head to predict a chunk of continuous actions directly, conditioned on the VLM’s output embedding: full continuous precision, better for smooth/fast manipulation, but needs a separate action-generation mechanism bolted onto the VLM, more moving parts. The discrete-token approach’s appeal is architectural laziness in the best sense: it needs no new machinery, just a bigger vocabulary and more training data. The continuous-head approach exists because binning inherently loses precision. For tasks like inserting a key into a lock, a discretised action space might not have a bin fine enough to succeed.

61.2.2 Why Internet Pretraining Transfers to Robot Actions

A VLA model built on a pretrained VLM backbone inherits that backbone’s visual and linguistic generalisation. It has already seen millions of images of objects in the world and learned what “the red mug” or “the object on the left” refers to, long before it saw a single robot trajectory. This is why VLA models generalise to novel objects and instruction phrasings far better than a policy trained from scratch on robot data alone, which only ever saw the specific objects and phrasings in its usually small, expensive-to-collect training set. The action-conditioned part of training is comparatively small and narrow; the visual/language competence it’s built on is broad and comes largely for free.

61.2.3 Where World Models Fit In

Some VLA training recipes add an auxiliary objective borrowed directly from Chapter 60: alongside predicting the next action, also predict what the next observation (or its embedding) will look like. The theory is that a model forced to predict consequences, not just imitate actions, learns richer internal structure, closer to understanding why an action works, not just that it was in the training data. This is an active research direction, not yet standard in every VLA architecture.

61.3 Trade-offs and Limits

The visual/language half of a VLA transfers broadly from pretraining, but the action-conditioned half still needs real (or simulated, Chapter 62) robot trajectory data, which is expensive and slow to collect compared to scraping the web for images and text. Control loops often need to run at 50-1000 Hz, and a multi-billion-parameter transformer forward pass does not fit inside a 20ms budget on typical hardware without serious optimisation. This is exactly why Chapter 64 exists: VLA inference in practice usually runs at a lower frequency than the underlying control loop, with a faster low-level controller handling the gap between VLA decisions. Binning a continuous action space trades precision for architectural simplicity. Coarse tasks (navigate to a room) tolerate this fine; precise tasks (thread a needle) may need a continuous action head instead.

61.4 Procedures

Procedure 61.1 (Choose an Action Representation). When to use: at the start of any VLA project, before writing any training code.

Common mistake: picking too few bins for a dimension that needs precision (e.g. 32 bins for gripper closure force) and then blaming the model architecture when the real problem is the discretisation grid.

Procedure 61.2 (Structure a VLA Fine-Tuning Dataset). When to use: before collecting or assembling training data for action-conditioned fine-tuning.

Structuring guidance: include the full instruction text, not a task ID. The point of a VLA is generalising to instruction phrasing it hasn’t seen verbatim. Vary phrasing for the same underlying task during data collection if possible, which is what teaches generalisation across phrasing rather than memorising one exact string.

61.5 Worked Example

A minimal VLA trained from scratch on a synthetic grid-world task: image observation, natural-language instruction, discrete action token output:

Epoch Loss
0 1.3462
5 0.3856
10 0.0028
20 0.0003
29 (final) 0.0001

Loss converges to near-zero, but per Chapter 60’s lesson about not trusting a loss curve alone, the real question is whether the model is genuinely conditioning on both the image and the instruction, or has found a shortcut that only needs one. A targeted ablation answers this directly by scrambling one modality at a time at evaluation time:

Condition Accuracy
Full (both modalities intact) 1.000
Instruction scrambled (image intact) 0.618
Image scrambled (instruction intact) 0.278
Majority-class baseline 0.316

Three findings, all measured rather than assumed. First, full accuracy (1.000) confirms the model solved the task completely when given genuine, matched image-instruction pairs. Second, both scrambling conditions drop accuracy well below full, proving the model genuinely depends on both modalities, not shortcutting past either one entirely (a model ignoring the instruction would show no drop when it’s scrambled; neither modality shows that). Third, and more informative: the two scrambled conditions aren’t symmetric. Scrambling the instruction (0.618) still leaves the model well above the majority-class baseline (0.316). The image alone carries substantial task-relevant signal on this dataset. Scrambling the image (0.278) drops accuracy to below the majority-class baseline. Without correct visual grounding, the model’s instruction-conditioned guesses are actively worse than simply guessing the most common action. This asymmetry is a genuine, task-specific finding about which modality this particular synthetic task leans on more heavily, not a general claim that vision always matters more than language for VLA models. A different task could show the opposite pattern, which is exactly why this ablation is worth running rather than assuming.

61.7 How This Connects

This chapter builds on Book 2’s transformers chapter (the attention/autoregressive-generation mechanism underlying every VLA’s action prediction), Book 2’s prompt engineering chapter (the language half of a VLA is, mechanically, an instruction-following language model), and Chapter 59 (VLA vision encoders do the same job as a dedicated perception pipeline, just trained jointly with the action head rather than as a separate stage). It enables Chapter 63, where a VLA-style policy is fine-tuned inside a simulator using imitation learning and reinforcement learning. It’s often confused with a generic multimodal chatbot that can describe an image and discuss what a robot should do, still purely language output, versus a VLA model, which outputs an actual action token consumed by a control system. Describing what to do and deciding what to do are architecturally different outputs, even when both are built on similar transformer backbones.

61.9 Mental Model

A VLA model is a language model whose vocabulary got bigger. It didn’t need a fundamentally new architecture to go from predicting words to predicting motor commands. It needed the same architecture, a wider output vocabulary, and training data that pairs observations and instructions with the actions that followed. Everything hard about VLA models, data collection, inference latency, precision, is an engineering problem layered on top of that simple idea, not a departure from it. This chapter’s Worked Example is a reminder that a converged loss curve proves the model fit something; only a targeted ablation, deliberately breaking one modality at a time, proves it fit the right something.
