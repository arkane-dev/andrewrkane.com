A fully-connected layer treats every pixel as an independent input with its own set of weights to every output. For a modest 224x224 colour image, that’s 150,528 inputs. A single fully-connected layer with even 1,000 hidden units needs over 150 million weights, all learned independently, none of them sharing what they learn about “what an edge looks like” with any other part of the image. Convolutional neural networks fix this by building in a structural assumption fully-connected layers ignore: what makes a feature useful doesn’t depend on where it appears in the frame. A cat’s ear looks like a cat’s ear whether it’s in the top-left or bottom-right of the photo.

68.1 Motivation

A convolution layer applies the same small set of weights, a kernel, at every position in the image, sliding across it. This weight sharing does two things at once: it makes the layer dramatically cheaper (a 3x3 kernel has 9 weights, not one weight per pixel pair), and it gives the network translation equivariance: if the input shifts, the feature map shifts with it, rather than the network relearning the same pattern separately for every possible position. Pooling (usually max-pooling) then does something subtly different: it discards exact position within a small window, keeping only the strongest response, converting convolution’s equivariance into translation invariance for classification purposes. After enough pooling, the network’s final answer stops caring exactly where in the image the relevant features fired. Getting these two words right matters: equivariant means “shifts with the input”; invariant means “doesn’t change when the input shifts.” Convolution alone is equivariant; convolution plus pooling, applied a few times, becomes progressively closer to invariant.

68.2 Exposition

68.2.1 Weight Sharing as an Inductive Bias

Every architecture makes some assumption about the structure of its input, stated or not. A fully-connected layer’s implicit assumption is “any input feature could matter for any output, in any position-specific way,” enormously flexible, but it has to learn spatial structure from scratch, from data, using far more parameters than the problem actually requires. A CNN’s implicit assumption, local patterns matter, and mean the same thing everywhere, happens to be true for natural images, so building it in for free, rather than making the network learn it, is a large efficiency win. Worked Example 68 below makes this concrete: a roughly 1,900-parameter CNN reaches real, measured 94.4% test accuracy on handwritten digits.

68.2.2 The Classic Architecture Lineage

LeNet (1989/1998, LeCun) is the original: a small number of conv+pool blocks followed by fully-connected layers, the blueprint every CNN since has followed at some level. AlexNet (2012) went deeper, swapped sigmoid/tanh for ReLU activations (which don’t saturate and vanish as badly, connects to Book 2’s intro-to-neural-networks chapter and its gradient discussion), added dropout for regularisation, and, critically, trained on GPUs, making a network this size practical for the first time. VGG (2014) pushed depth further with a simple, uniform design: stack many small 3x3 convolutions instead of a few large ones. Stacking small kernels grows the receptive field just as effectively as a few large kernels, at lower parameter cost, and VGG’s insight was to lean into that fully.

68.2.3 Where This Hits a Wall

VGG-style “just stack more 3x3 layers” doesn’t scale indefinitely. Push a plain (no skip connections) CNN much past roughly 20 layers and something counterintuitive happens: it doesn’t just get harder to train, it gets outright worse, even on the training set, where more capacity should help, not hurt. That’s the vanishing-gradient problem specifically as it hits stacked convolutions, and it’s the exact problem Chapter 69 exists to solve. This chapter’s job is building the CNN vocabulary; Chapter 69 explains why depth alone stops helping and what residual connections do about it.

68.3 Trade-offs and Limits

Kernel size versus depth: a single large kernel (7x7) covers more of the image per layer than a small one (3x3), but costs more parameters per layer for the same receptive field. Stacking small kernels (VGG’s approach) usually wins on parameter efficiency, at the cost of needing more layers, and eventually running into the vanishing-gradient wall. Pooling versus strided convolution: max-pooling is a fixed, non-learned downsampling operation; a strided convolution (stride > 1) downsamples and learns what to keep in the process. Modern architectures increasingly prefer strided convolutions or learned downsampling, though pooling remains simple, cheap, and effective enough to still show up everywhere. Data augmentation isn’t free, and Worked Example 68 measures this directly rather than assuming it: augmentation’s benefit has to be calibrated to the data’s actual scale, not applied by default because a tutorial said so.

68.4 Procedures

Procedure 68.1 (Calculate Conv/Pooling Output Dimensions). When to use: designing a CNN architecture, to know what spatial size each layer produces before the final flatten/fully-connected layer.

Common mistake: getting the flatten dimension wrong for the first fully-connected layer. Compute it explicitly for every conv/pool layer in sequence rather than guessing; a one-off error here is the single most common reason a new CNN throws a shape-mismatch error on the first forward pass.

68.5 Worked Example

A roughly 1,900-parameter CNN (two small conv+pool blocks followed by a small fully-connected head) trained on real handwritten digit images reaches 94.4% test accuracy, a concrete, measured confirmation of Exposition’s efficiency claim: a network with fewer parameters than a single small fully-connected layer would need for one image’s raw pixels achieves strong accuracy specifically because weight sharing lets it reuse the same learned edge/stroke detectors across every position in the image, rather than learning position-specific weights from scratch.

A second experiment, seed-averaged over 8 runs, tests Trade-offs’ data-augmentation claim directly rather than assuming augmentation helps by default:

Condition Test accuracy (mean ± std over 8 seeds)
No augmentation 0.874 ± 0.016
With augmentation (small shifts + mild noise) 0.866 ± 0.013

Augmentation gave essentially no benefit, if anything, a small, likely-noise-level decrease. At this resolution (small, low-resolution digit images), standard augmentation strengths tuned for much larger natural images are proportionally too aggressive to help: a “small” pixel shift calibrated for a 224x224 photo is a much larger fraction of an 8x8 digit’s total content, effectively corrupting the digit rather than mildly perturbing it. This is Trade-offs’ warning made measurable: augmentation’s benefit has to be measured and calibrated to a dataset’s actual scale, not applied by default because a general tutorial or library default recommends it.

68.9 Mental Model

A convolution layer is a small, cheap, reusable pattern detector applied everywhere in the image at once. Pooling then throws away exactly where a pattern fired, keeping only that it fired. Stack a few rounds of “detect local patterns, discard exact position, detect patterns-of-patterns” and the network moves from raw pixels to increasingly abstract, position-independent features: edges, then textures, then parts, then whole objects. This chapter’s Worked Example is a reminder that not every standard technique transfers automatically to a new data scale: augmentation is a real, useful tool for natural photos, and a measured non-improvement on tiny digit images, both true at once.
