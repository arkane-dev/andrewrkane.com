Chapter 68 ended on a puzzle: VGG-style “just stack more 3x3 conv layers” doesn’t scale indefinitely. Push a plain deep network far enough and it doesn’t merely get harder to optimise. It gets worse, even on the training set it’s being fit to, which is not what “more capacity” is supposed to do. This chapter explains why, and what fixed it.

69.1 Motivation

Backpropagation computes gradients by the chain rule, multiplying together the local derivative of each layer as it flows backward from the loss to the earliest layers. If each layer’s local derivative is somewhat less than 1 (common with saturating activations, and plausible even without them given enough layers) the product of twenty or fifty such terms shrinks toward zero, the vanishing gradient problem. Early layers in a very deep plain network end up receiving a gradient signal so weak they barely update, regardless of data volume or epoch count. ResNet’s fix (He et al., 2015) is a residual (skip) connection: instead of a block learning a function H(x)H(x)H(x) directly, it learns a residual F(x)=H(x)−xF(x) = H(x) - xF(x)=H(x)−x, and the block’s actual output is F(x)+xF(x) + xF(x)+x. This does two things: it gives gradients a direct, additive path back through the network, bypassing the multiplicative chain. The gradient of F(x)+xF(x) + xF(x)+x with respect to xxx always includes a +1+1+1 term from the identity path, so it can’t vanish to exactly zero purely from stacking more blocks. And it makes “do nothing” the easiest thing for a block to learn, since driving F(x)F(x)F(x) toward zero makes the block approximate the identity function, letting the network effectively skip a block it doesn’t need. Worked Example 69 below measures this effect directly on a plain and a residual network of identical size.

69.2 Exposition

69.2.1 The ResNet Family

ResNet is named by depth: ResNet-18 and ResNet-34 use simple two-conv residual blocks; ResNet-50/101/152 use a “bottleneck” block (1x1 conv to reduce channels, 3x3 conv, 1x1 conv to restore channels) that’s cheaper per layer, allowing much greater depth at a similar compute budget. The core skip-connection idea is unchanged across the family. Only internal block design and depth scale.

69.2.2 Other Answers to “How Do We Scale CNNs Well”

Inception (GoogLeNet, 2014) takes a different approach: instead of one path per layer, an Inception block runs several convolutions of different kernel sizes in parallel on the same input and concatenates the results, letting the network choose what scale of feature matters at each stage rather than committing to one kernel size per layer. EfficientNet (2019) asks a different question entirely: given a fixed compute budget, how should it split between network depth, width, and input resolution? Prior work tended to scale just one of these; EfficientNet’s compound scaling, found via neural architecture search, scales all three together in a fixed ratio, reliably outperforming naive single-axis scaling at the same compute cost. Neither is a “better ResNet.” They answer a related but distinct question (how to allocate a fixed compute budget for best accuracy) rather than ResNet’s specific question (how to make very deep networks trainable at all).

69.2.3 Transfer Learning: Feature Extraction vs. Fine-Tuning

A network pretrained on a large, diverse dataset (canonically ImageNet) learns, in its early and middle layers, features broadly useful well beyond the specific classes it was trained to recognise: edge detectors, texture detectors, colour-gradient detectors. This is transfer learning’s entire premise: reuse that already-learned visual vocabulary instead of relearning it from a small target dataset. Feature extraction freezes every pretrained weight and trains only a new final layer, cheap and least prone to overfitting since almost the entire network’s parameters are fixed. Fine-tuning unfreezes some (often later) layers too, continuing training them at a much smaller learning rate than the new head, to avoid destroying the pretrained weights’ useful structure in a few noisy gradient steps. Neither approach is a free win. Worked Example 69 measures this directly, and somewhat against the grain of how transfer learning is usually pitched.

69.3 Trade-offs and Limits

Depth alone stopped being free once networks got deep enough for vanishing gradients to bite. ResNet’s contribution wasn’t “add more layers,” it was “make more layers actually trainable.” Choosing between feature extraction, fine-tuning, and from-scratch depends on two things: how similar the target domain is to the pretraining domain, and how much target data is available. Similar domain plus little data favours feature extraction or light fine-tuning; similar domain plus lots of data favours more aggressive fine-tuning; very different domain plus little data can mean a well-matched from-scratch model beats both, as Worked Example 69 demonstrates directly. Given a fixed compute budget, more depth, more width, and higher resolution all cost compute differently and interact. EfficientNet’s compound scaling is one principled answer to where that budget should go.

69.4 Procedures

Procedure 69.1 (Add a Residual/Skip Connection). When to use: building a deep CNN (roughly 15+ conv layers) from scratch, or adapting a plain architecture underperforming as depth increases.

Common mistake: trying to add a block’s output directly to its input when channel counts or spatial dimensions don’t match. This throws a shape error. Use a 1x1 projection convolution on the shortcut path whenever a block changes shape.

Procedure 69.2 (Decide: Feature Extraction, Fine-Tuning, or From Scratch). When to use: starting a new vision task and deciding whether to reach for a pretrained model at all.

Procedure 69.3 (Set Up Feature Extraction). When to use: target domain reasonably similar to the pretraining domain, small target dataset.

69.5 Worked Example

A plain and a residual CNN, identical depth, width, and parameter count, trained identically on the same digit-classification task:

Epoch Plain train acc. Residual train acc.
10 0.687 0.998
30 0.992 1.000
60 0.981 1.000
Model Final test accuracy
Plain 0.958
Residual 0.989

The gap is starkest early: by epoch 10, the residual network has already essentially converged (0.998 train accuracy) while the plain network is still well below full accuracy (0.687), a direct, measured demonstration of Motivation’s claim that skip connections give gradients a faster, more direct path back through the network. The plain network eventually catches up substantially on training accuracy (0.981 by epoch 60) but never quite matches the residual network’s final test accuracy (0.958 vs. 0.989). With identical parameter count, identical depth, and identical training budget, the only difference is the skip connections.

A second experiment tests the transfer-learning trade-off directly, comparing three approaches on the same target task, a domain visually quite different from ImageNet’s natural photos:

Approach Trainable parameters Test accuracy
Feature extraction 5,130 0.633
Fine-tuning 8,398,858 0.561
From scratch 3,658 0.842

This is the trade-off measured directly, somewhat against the grain of how transfer learning is usually pitched: the from-scratch model, with fewer parameters than the feature-extraction head alone, and over 2,000x fewer trainable parameters than the fine-tuned model, wins outright. Feature extraction’s pretrained ImageNet features transfer only weakly to this visually different target domain, capping its usefulness. Fine-tuning does worse than feature extraction despite unfreezing far more capacity, because that capacity became a liability on a small target dataset. 8.4 million trainable parameters is a lot to overfit with on limited target data, exactly Trade-offs’ warning about fine-tuning’s overfitting risk. Per Procedure 69.2’s guidance, this is precisely the “very different domain, little data” cell where a well-matched from-scratch model can beat both transfer-learning approaches, and the only way to know that in advance would have been testing all three, not assuming transfer learning always wins.

This chapter builds on Chapter 68 (ends on the vanishing-gradient wall this chapter resolves) and Book 1’s calculus/optimization chapter, which covers gradient flow and vanishing/exploding gradients generically. It enables Chapter 70 (detection/segmentation models typically use a ResNet-family backbone) and Chapter 71 (Vision Transformers are a different, non-convolutional answer to some of the same scaling questions). It’s often confused with “deeper is always better.” It isn’t, on its own; ResNet’s insight was specifically about making depth trainable, not that depth alone improves accuracy without bound, and this chapter’s transfer-learning result is a second, independent caution against a different “obviously true” assumption (pretrained transfer always helps) that measurement contradicted directly.

69.9 Mental Model

A residual block’s default behaviour, before any training signal pushes it otherwise, is close to “pass the input through unchanged.” Training then has to actively carve out a deviation from that default wherever a deviation genuinely helps, rather than a plain network, where every layer has to actively get its full transformation right just to preserve what the previous layer already learned. This chapter’s Worked Example demonstrates that reframing measurably: the residual network converges within 10 epochs to what the plain network never quite reaches by epoch 60. The transfer-learning experiment adds a second lesson in the same spirit as the whole book’s throughline: “pretrained features always help” and “deeper is always better” are both intuitions that measurement, not assumption, has to settle.
