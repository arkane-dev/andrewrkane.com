Every model built so far in this track has judged one modality against itself: a classifier’s accuracy against labels drawn from a fixed set (Chapters 68 and 71), or a generative model’s samples eyeballed by a human (Chapters 72 and 73). Two problems follow directly from that. First: how does a model connect an image to free-form natural language rather than a fixed label set, “a photo of a dog on a beach” rather than class index 3? Second, and just as important: once a model can generate images from text, exactly what Chapter 73’s classifier-free guidance made possible, how does anyone know if the result is actually good, without a human staring at every sample? This chapter answers both. CLIP is the standard architecture for connecting vision and language into one shared space. FID, Inception Score, and CLIPScore are the standard tools for turning “does this look right?” into a number.

74.1 Motivation

CLIP’s idea is to train an image encoder and a text encoder together, with no classification labels at all, using only the fact that some (image, text) pairs genuinely belong together and others don’t. Matched pairs’ embeddings get pushed close together in a shared space; everything else gets pushed apart. Nothing in that objective mentions “dog” or “cat” as a fixed category, so at inference time, any text prompt can be embedded and compared against any image, with no retraining. Evaluation follows the same shift away from fixed categories: instead of asking a human to eyeball generated images, both real and generated images get pushed through a fixed, strong feature extractor, and the resulting feature vectors are compared mathematically: a distributional distance (FID), a confidence/diversity measure (Inception Score), or a direct image-text similarity (CLIPScore, using CLIP itself as the judge).

74.2 Exposition

74.2.1 Contrastive Alignment Forces Genuine Correspondence, Not Memorization

For a batch of NNN (image, caption) pairs, CLIP builds the full N×NN \times NN×N similarity matrix between every image embedding and every text embedding. The diagonal holds the correct pairs; everything off-diagonal is a mismatch. Training treats “which caption matches this image” as an NNN-way classification problem, applied symmetrically in both directions (image-to-text and text-to-image) and averaged:

L=12(CE(s⋅ZimgZtxt⊤, diag)+CE(s⋅ZtxtZimg⊤, diag))\mathcal{L} = \frac{1}{2}\Big(\text{CE}(s \cdot Z_{\text{img}} Z_{\text{txt}}^\top,\, \text{diag}) + \text{CE}(s \cdot Z_{\text{txt}} Z_{\text{img}}^\top,\, \text{diag})\Big)L=21​(CE(s⋅Zimg​Ztxt⊤​,diag)+CE(s⋅Ztxt​Zimg⊤​,diag))

where ZimgZ_{\text{img}}Zimg​ and ZtxtZ_{\text{txt}}Ztxt​ are L2-normalized embedding matrices, sss is a learnable temperature (logit_scale), and diag is the target that the iii-th image matches the iii-th caption. Training both directions matters: optimizing image-to-text alone lets the text encoder collapse to anything locally distinguishable, since nothing forces the text side to build a genuinely shared, mutually consistent space with the image side.

74.2.2 Zero-Shot Classification Is the Direct Payoff of a Shared Space

Once image and text embeddings live in the same space, “classify this image” becomes “which of these candidate text prompts is closest?” No classifier head, no fine-tuning step. A prompt is built per class ("a photo of the digit {word}"), all class prompts are embedded once, and a new image is classified by cosine similarity against that fixed set of class embeddings. Nothing about this requires the model to have ever seen those exact class prompts as training targets. Only genuinely-learned alignment between images and any accurate description of them generalizes to prompts constructed after training is finished.

74.2.3 CLIPScore Is the Training Objective, Reused as a Metric

CLIPScore, as an evaluation metric for image captioning or text-to-image generation, is nothing more than the same cosine similarity CLIP’s contrastive loss already optimizes, computed at evaluation time instead of training time. A well-aligned model’s genuine caption for an image should score noticeably higher than an unrelated one. The same signal the loss pushed apart during training becomes the number reported at evaluation time.

74.2.4 FID and Inception Score Use a Feature Extractor as a Stand-In for “Looks Real”

Neither metric asks a human “does this look real?” Both push images through a fixed feature extractor (real FID and Inception Score use a pretrained Inception-v3, though any sufficiently strong feature extractor plays the same structural role) and compute a statistic over the resulting feature vectors.

FID treats each image set’s feature vectors as samples from a multivariate Gaussian and computes the Fréchet distance between the two Gaussians:

FID(X,Y)=∥μX−μY∥2+Tr(ΣX+ΣY−2(ΣXΣY)1/2)\text{FID}(X, Y) = \lVert \mu_X - \mu_Y \rVert^2 + \text{Tr}\big(\Sigma_X + \Sigma_Y - 2(\Sigma_X \Sigma_Y)^{1/2}\big)FID(X,Y)=∥μX​−μY​∥2+Tr(ΣX​+ΣY​−2(ΣX​ΣY​)1/2)

Lower is better. Zero is reached only in the limit of infinite identical samples, so a real-vs-real baseline computed by splitting one dataset in half is the practical floor to compare against, not zero itself.

Inception Score instead looks at classifier confidence. For each image, p(y∣x)p(y|x)p(y∣x) is the predicted-class distribution: a good image should produce a sharp p(y∣x)p(y|x)p(y∣x) (it clearly looks like one thing). Across the whole generated set, p(y)p(y)p(y) is the marginal class distribution: a good generator should produce a broad p(y)p(y)p(y) (variety, not one repeated output). Inception Score rewards both at once:

IS=exp⁡(Ex[KL(p(y∣x) ∥ p(y))])\text{IS} = \exp\Big(\mathbb{E}_x\big[\text{KL}(p(y|x) \,\|\, p(y))\big]\Big)IS=exp(Ex​[KL(p(y∣x)∥p(y))])

Higher is better, and it moves in the opposite direction from FID. The two metrics tell the same underlying story about image quality via completely different mathematics (classifier-confidence entropy versus Gaussian distributional distance), which is exactly why checking that they agree is a genuine cross-check rather than a redundant one.

74.3 Trade-offs and Limits

CLIP’s zero-shot flexibility trades against task-specific accuracy: a model trained end-to-end for one specific classification task, on that task’s own labels, will typically beat a zero-shot CLIP-style model on that exact task. CLIP’s advantage is never needing to retrain when the task or label set changes, not raw peak accuracy on any single fixed task. FID, Inception Score, and CLIPScore are all proxies, not ground truth, for the same underlying reason: a feature extractor captures whatever it learned to represent, and any bias or blind spot in that extractor becomes a blind spot in the metric built on top of it. That is exactly why computing two structurally different metrics and checking they agree, rather than trusting either alone, is standard practice, not paranoia. Any toy-scale version of these ideas (small encoders, synthetic captions, a handful of classes) validates the mechanism, not the scale: real CLIP’s advantage comes from training on hundreds of millions of genuinely diverse image-caption pairs with an open vocabulary, a far harder setting than a small, well-separated classification problem with templated captions.

74.4 Procedures

Procedure 74.1 (Build a Symmetric Contrastive Training Batch). When to use: training any dual-encoder model that needs to align two modalities (image/text, image/image, text/text) without classification labels.

Diagnostic: compare the first-epoch loss to ln(batch_size). That is the exact loss value a fully untrained, random-similarity model produces by construction. If the first-epoch loss is far from this, check the loss implementation before suspecting the model architecture. Common mistake: forgetting to normalize before the dot product. Without normalization, the loss can trivially “cheat” by inflating embedding magnitude rather than learning genuine directional alignment.

Procedure 74.2 (Zero-Shot Classification via Text Prompts). When to use: using a trained CLIP-style model for classification with no classifier head and no fine-tuning.

Common mistake: inconsistent prompt wording between classes ("a photo of a dog" versus a bare "cats" with no article or template). Real CLIP deployments often try several prompt templates per class and average the resulting embeddings (“prompt ensembling”) specifically because wording measurably affects zero-shot accuracy, a preview of the broader lesson in Book 2, Chapter 30 (Prompt Engineering): how a query is phrased changes what a model returns, even when the underlying task hasn’t changed.

Procedure 74.3 (Compute CLIPScore for a Batch of Image-Caption Pairs). When to use: evaluating image captioning quality, or how well a generated image matches its text prompt. Reference-free, with no “ground truth” image required, only the (image, text) pair being judged.

Procedure 74.4 (Compute FID Between Two Image Sets). When to use: judging overall distributional realism of a generated image set against real data.

Common mistake: computing FID on too few images. Both sets need enough samples that np.cov produces a stable estimate. A handful of images gives a meaningless, or numerically unstable, covariance matrix. Sanity check before trusting an FID number: compute FID between two random splits of the same real dataset first. That is the practical “best case” baseline, since true zero only happens with infinite identical samples.

Procedure 74.5 (Compute Inception Score). When to use: judging a generative model’s output sharpness and diversity without needing a separate real reference set, unlike FID, which always compares two sets.

Common mistake: treating Inception Score as sufficient on its own. A generator that repeats a single, confidently-classified image over and over can still score deceptively well on some IS variants if diversity isn’t checked separately. One reason FID, which explicitly compares distributions rather than per-image confidence, is generally preferred as the primary metric, with IS as a secondary check.

Procedure 74.6 (Sanity-Check Any New Evaluation Metric Before Trusting It). When to use: a new image-generation evaluation metric has just been implemented, or someone else’s implementation is being adopted, and needs to be trusted before it drives a real ship decision.

Why this matters: if a metric does not move monotonically through this real-to-degraded-to-noise gradient, it should not be trusted for judging a real generative model’s output. The metric implementation or feature extractor needs debugging first, before it is used for anything downstream.

74.5 Worked Example

The tutorial notebook behind this chapter builds a small CLIP-style dual encoder: the exact patch-embedding, [CLS]-token, transformer-encoder image architecture from Chapter 71, paired with a bag-of-embeddings text encoder, trained with Procedure 74.1 on 8x8 digit images (sklearn’s digits dataset) and synthetic captions drawn from three templates ("a photo of the digit {w}", "a drawing of the number {w}", "handwritten digit showing {w}"), so no single caption string could simply be memorized per image.

With a batch size of 64, the untrained-model reference loss is ln⁡(64)=4.1589\ln(64) = 4.1589ln(64)=4.1589. The measured first-epoch loss, 4.2165, lands almost exactly there, confirming the loss implementation is correct before training even begins. Training drove the loss down to a converged 2.0043, direct evidence of genuine learned alignment, not a lookup table.

Zero-shot classification (Procedure 74.2), using the canonical template only, reached 96.9% accuracy on 360 held-out test images, against a 10% chance baseline. This is despite the model never once training against those 10 exact canonical prompts as fixed targets, only against randomly-varied templates. That gap between training-time captions and inference-time prompts, with the model still working, is what “zero-shot” means in practice.

74.7 How This Connects

This chapter’s image encoder reuses Chapter 71 (Vision Transformers)’s patch-embedding and transformer-encoder architecture outright. CLIP’s original image encoder is exactly a ViT, or in some variants a ResNet, but a ViT is the more common modern choice and the one built here. Classifier-free guidance’s conditioning mechanism, built in Chapter 73 (Diffusion Models), is exactly how a real text-to-image diffusion model uses embeddings like the ones built here. The only change is swapping Chapter 73’s one-hot class labels for CLIP text embeddings as the conditioning signal. This chapter enables Chapter 75 (Capstone: Image Models): evaluating a generative pipeline honestly, rather than eyeballing samples, is precisely the discipline the capstone project needs. It is often confused with treating FID, Inception Score, and CLIPScore as objective ground truth rather than proxies computed through a specific, imperfect feature extractor. This chapter’s own trained-encoder-as-Inception-substitute is a deliberately visible example of exactly that limitation.

74.9 Mental Model

CLIP does not learn “what a dog looks like” as a fixed category. It learns a shared space where an image and any accurate description of it end up close together, and everything else ends up far apart. FID and Inception Score do not ask “does this look real?” directly either. They ask “do this image set’s feature statistics resemble real images’ feature statistics, according to some fixed feature extractor?” Both replace a fixed, closed-set judgment with a flexible, measurable one, which is more useful, but only as trustworthy as the feature extractor or embedding space it is built on.
