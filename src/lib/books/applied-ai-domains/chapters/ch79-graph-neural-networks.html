Chapter 76 gave exact, deterministic answers about graph structure (a node’s PageRank, its betweenness, which community it falls into) computed by a fixed formula, no training required. That works well as long as the question is purely structural. But real problems are often messier: “is this transaction fraudulent, given who it’s connected to,” or “what’s the likely relationship between these two entities never directly observed together” aren’t questions a fixed formula answers. They need a model that has learned from examples what patterns of connection tend to mean. This chapter is where the approach shifts from “compute an exact structural property” to “learn a representation,” the same shift Book 1 made going from classical ML to neural networks, applied to graph-shaped data instead of tabular or sequential data.

79.1 Motivation

A graph neural network learns a vector for each node such that the vector reflects both the node’s own information and its position in the graph. Three ways to do this, all measured directly in Worked Example 79: GCN (supervised: given a few labelled nodes, learn representations via repeated neighbourhood aggregation that let labels be predicted for the rest), node2vec (unsupervised: given only graph structure, learn representations such that nodes co-occurring in random walks end up close together in vector space), and TransE (unsupervised, for typed relations: learn entity and relation vectors such that head + relation ≈ tail for every true fact). All three replace “apply a formula” with “learn parameters from data,” making the same fundamental bet Chapter 76’s algorithms made, that graph structure alone carries usable signal, extracted through gradient descent instead of a closed-form formula.

79.2 Exposition

79.2.1 Message Passing: The One Idea Behind Every GNN Variant

Every GNN variant (GCN, GraphSAGE, GAT, and dozens more in the wider literature) is a version of the same pattern: each node updates its own representation by aggregating its neighbours’ representations, then applying a learned transformation. Stack several such layers, and a node’s final representation has been influenced by every node within that many hops. A 2-layer GCN’s output for node A has “seen” A’s neighbours and its neighbours’ neighbours, without ever being told explicitly to look 2 hops away. The GCN’s specific aggregation, D^−1/2(A+I)D^−1/2\hat{D}^{-1/2}(A+I)\hat{D}^{-1/2}D^−1/2(A+I)D^−1/2, is a symmetric, degree-normalised average: every node’s neighbours are averaged (with self included via the +I self-loop), scaled so high-degree nodes don’t dominate purely by having more connections.

79.2.2 Why This Needs No Node Features At All

Worked Example 79’s GCN is given an identity matrix as input features: every node starts as “featureless” except for a one-hot marker of its own identity. That the model still classifies almost every node correctly is the clearest possible demonstration that the graph’s connectivity pattern alone is enough signal, without any node attributes at all. In practice real node features would typically also be fed in. This is what makes GNNs so useful for fraud detection, combining a transaction’s own features with who it’s connected to, but the mechanism doesn’t require them.

79.2.3 node2vec: Borrowing word2vec’s Trick, Applied to Walks Instead of Sentences

node2vec’s insight is a direct transplant from NLP (Chapter 27’s embeddings): treat a random walk over a graph as a “sentence” of node IDs, and the same skip-gram objective that learns word embeddings from co-occurring words learns node embeddings from co-occurring graph positions. Two nodes that show up near each other in many random walks, because they’re structurally close, well-connected, or in the same dense cluster, end up with similar embeddings, with no labels used anywhere in training.

79.2.4 TransE: Relations as Geometric Translations

TransE makes a specific, falsifiable geometric bet: that a relationship like “owned by” can be represented as a single vector that, when added to any owned company’s vector, lands close to its owner’s vector, for every true OWNED_BY fact simultaneously. This is a strong assumption (real relations aren’t always this simple: a company can have multiple owners, a relation might not compose this cleanly), which is exactly why TransE has known limitations and why later, more expressive models (TransR, RotatE, ComplEx) exist. But the assumption is remarkably effective at the scale Worked Example 79 uses, recovering typed relational facts entirely from structure: no text, no external features, just the constraint that true triples satisfy h+r≈th + r \approx th+r≈t better than corrupted ones.

79.3 Trade-offs and Limits

A GCN is transductive: trained against a specific, fixed graph, it doesn’t natively handle new nodes it never saw during training. GraphSAGE fixes this by learning an aggregation function rather than fixed per-node weights, applicable to unseen nodes at inference time. GAT adds learned attention weights so not every neighbour contributes equally, useful when some neighbours are clearly more relevant, at the cost of more parameters and compute. Supervised (GCN) versus unsupervised (node2vec, TransE): a GCN needs labels, often expensive or unavailable at the scale desired; node2vec and TransE need none, but as a direct consequence can only optimise for “structure looks similar,” not for whatever specific downstream task actually matters. Worked Example 79’s node2vec validation check uses labels only to check the unsupervised embeddings, never to train them, precisely because that’s the honest way to validate an unsupervised method when ground truth happens to be available. TransE’s structural assumption is a real limitation, not just a design choice: because it insists every relation is a single additive translation, it struggles with relations that aren’t 1-to-1 in that simple sense. A company having multiple owners violates the geometry, which is what motivates more expressive successor models.

79.5 Worked Example

GCN, trained on the Zachary karate club graph (34 nodes, 78 edges, two real-world factions), with only 4 of 34 nodes labelled (11.8% of the graph) and node features deliberately set to the identity matrix: the model sees only structure, no attributes:

Epoch Train loss Test accuracy
0 0.7187 0.5000
50 0.0008 0.9667
150 (final) 0.0027 0.9667

Final test accuracy 0.9667 against a majority-class baseline of 0.5000, on the 30 nodes never shown a label. The label signal from just 4 nodes propagated outward through the graph’s structure alone (no node attributes whatsoever) to correctly classify nearly every remaining node, exactly Exposition’s claim about connectivity-alone signal, made numeric.

node2vec, trained fully unsupervised (680 random walks, 23,120 center/context pairs, skip-gram objective, no labels used anywhere in training) on the same graph:

Metric Value
node2vec: same-faction rate among top-3 nearest neighbours 0.9412
Random-embedding baseline 0.5490

Nodes’ nearest neighbours in the learned embedding space share the correct real-world faction 94.12% of the time, dramatically above the 54.90% random-embedding baseline, recovering most of the same real-world structure Chapter 76’s supervised-against-ground-truth community detection also found, but via an entirely different, fully unsupervised mechanism with zero labels used in training.

TransE, trained on a tiny typed-relation knowledge graph (12 entities, 4 relation types, 13 triples): OWNED_BY, SUPPLIES, EMPLOYS, LOCATED_IN facts, learned entirely from structure:

Every true fact’s correct tail entity ranks within TransE’s top 3 predictions (Hits@3 = 1.0000), and the mean rank of 1.0769 is nearly perfect (1.0 would mean every correct answer ranked first every time). A concrete example: querying 'Acme Corp OWNED_BY ?' returns ['Zenith Holdings', 'Orion Group', 'Acme Corp'] as its top-3 predicted tails. The ground truth, Zenith Holdings, ranks first, recovered purely from the geometric constraint h+r≈th + r \approx th+r≈t, with no text or external features involved at all.

It’s often confused with assuming a GNN “sees” the whole graph like a human reading a diagram. It only ever aggregates local neighbourhoods, layer by layer; a 2-layer GCN literally cannot use information from a node more than 2 hops away, however important that distant node might be.

79.9 Mental Model

Chapter 76 asked exact structural questions and got exact structural answers. This chapter asks the same kind of question (how does this node relate to the rest of the graph?) but answers it by learning a vector through gradient descent instead of computing a formula, trading determinism and interpretability for flexibility: a learned embedding can capture patterns no human-designed formula anticipated, at the cost of needing training, data, and, for the supervised case, at least some labels to learn from. This chapter’s three Worked Examples show that trade-off paying off three different ways: 4 labels propagating to 30 correct predictions, zero labels recovering 94% faction agreement, and 13 triples recovering a near-perfect relational structure, all from connectivity alone.
