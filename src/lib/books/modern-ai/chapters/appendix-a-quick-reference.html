Hand-Rolled ROUGE (No Library Needed)

from collections import Counter

def rouge1(reference, candidate):
    ref_c = Counter(reference.lower().split())
    cand_c = Counter(candidate.lower().split())
    overlap = sum((ref_c & cand_c).values())
    precision = overlap / len(cand_c) if cand_c else 0
    recall = overlap / len(ref_c) if ref_c else 0
    return precision, recall

Chapter 35 — Reinforcement Learning & RLHF

Key Terms

Term Definition
Agent The language model being trained (the policy)
Environment The conversation / prompt context
State Tokens generated so far
Action The next token emitted, or, coarsely, the full response
Reward Scalar score from a reward model for a full response
Policy (πθ\pi_\thetaπθ​) The LLM being trained
Reference policy (πref\pi_{ref}πref​) A frozen copy of the starting (usually SFT) model: the KL anchor
Reward hacking The policy exploits a proxy reward signal in a way that scores well but is actually bad
Bradley-Terry model Pairwise-comparison loss used to train a reward model from preference pairs

PPO-Based RLHF vs. DPO

PPO-based RLHF DPO
Needs a separate reward model Yes: trained first, then frozen during policy optimisation No: preference pairs used directly
Needs online sampling during training Yes: policy generates rollouts every step No: ordinary supervised training on static pairs
Hyperparameter sensitivity High (clip ratio, value-function coefficient, KL coefficient, GAE lambda, …) Low (mainly beta and learning rate)
Compute cost High Comparable to SFT
Produces a reusable reward model Yes No
Typical trl class PPOTrainer DPOTrainer
Best for Teams with RL infra and a reward-model use case beyond this run (best-of-N, data filtering) Default choice for most preference-tuning

Key Formulas

Bradley-Terry preference loss (reward model training): L=−log⁡σ(r(chosen)−r(rejected))\mathcal{L} = -\log \sigma(r(\text{chosen}) - r(\text{rejected}))L=−logσ(r(chosen)−r(rejected)) r(⋅)r(\cdot)r(⋅) is the reward model’s scalar output for a (prompt, response) pair. Minimised by maximising the score gap between chosen and rejected. Never demands an absolute reward value.

KL-constrained RL objective (what PPO-based RLHF maximises): Objective=E[r(response)]−β⋅KL(πθ(⋅∣prompt) ∥ πref(⋅∣prompt))\text{Objective} = \mathbb{E}[r(\text{response})] - \beta \cdot \text{KL}(\pi_\theta(\cdot|\text{prompt}) \,\|\, \pi_{ref}(\cdot|\text{prompt}))Objective=E[r(response)]−β⋅KL(πθ​(⋅∣prompt)∥πref​(⋅∣prompt))

DPO loss (closed-form, no reward model or RL loop): LDPO=−log⁡σ ⁣(β[log⁡πθ(chosen∣p)πref(chosen∣p)−log⁡πθ(rejected∣p)πref(rejected∣p)])\mathcal{L}_{DPO} = -\log \sigma\!\left(\beta \left[\log\frac{\pi_\theta(\text{chosen}|p)}{\pi_{ref}(\text{chosen}|p)} - \log\frac{\pi_\theta(\text{rejected}|p)}{\pi_{ref}(\text{rejected}|p)}\right]\right)LDPO​=−logσ(β[logπref​(chosen∣p)πθ​(chosen∣p)​−logπref​(rejected∣p)πθ​(rejected∣p)​])

Both formulas use the same β\betaβ: it controls how tightly the policy is leashed to the reference model.

beta Starting Points and Symptoms

Symptom Likely cause Fix
Policy output barely changes after training beta too high Lower it (try 0.05, 0.02)
Output degenerates: repetition, off-topic, exploits reward model beta too low Raise it (try 0.2, 0.5)
DPO loss goes to ~0 almost immediately Learning rate too high, or too few unique preference pairs Lower LR to 1e-6–5e-6; add more diverse pairs
Training loss looks fine but LLM-judge win rate doesn’t improve Reward hacking or preference-data quality issue Inspect generations directly; check preference-label consistency

Default starting point: beta = 0.1, learning_rate = 5e-6 (DPO); same order of magnitude for PPO’s KL coefficient.

Failure Mode Cheat Sheet

Failure Cause Mitigation
Infinite/near-infinite loop Ambiguous tool result, model retries Hard step-limit guardrail
Tool misuse Plausible-looking wrong arguments Narrow, well-described schemas
Compounding errors Bad early observation poisons later context No full fix: minimize + catch early
Cost/latency blowup Every step is a full model call Bound steps; prefer fewer, well-scoped tools

def run_agent(task, max_steps=6):
    trajectory = []
    for step in range(1, max_steps + 1):
        decision = policy(step, trajectory)
        if decision is None:
            return {"status": "answered", "trajectory": trajectory}
        result = TOOLS[decision["action"]](**decision["args"])
        trajectory.append({
            "step": step, **decision, "observation": result
        })
    return {
        "status": "step_limit_reached",
        "trajectory": trajectory,
    }
